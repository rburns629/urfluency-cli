# Release notes

What changed in each release of the urFluency CLI, newest first. The release
workflow publishes a version's section as its GitHub release, and the website
shows it at urfluency.com/about/releases.

Each section is headed `## vX.Y.Z (YYYY-MM-DD)`. An optional first paragraph
sums up the release in one line. Each change is a bullet that starts with
`New:`, `Improved:`, `Fixed:`, or `Security:`, written for people who use the
CLI rather than for people who work on it.

## v1.3.0 (unreleased)

- Improved: Uploads say under which rules you dismissed findings, as a count per rule id, so urFluency can see which rules people judge wrong and tune them. They still never say which findings: no file, line, or code. `upload --dry-run` shows exactly what is sent.

## v1.2.2 (2026-11-03)

Fewer false security findings in Python, found by calibrating scores against reviewer ratings.

- Fixed: Python's security checks skip tests, and py.sql-string-built reports a value spliced where SQL expects one, not table and column names, quoted identifiers, or placeholder lists that database backends format in. On Django, SQLAlchemy, Flask, and Requests their findings fell from 327 to 44.

## v1.2.1 (2026-11-03)

Fewer false findings across seven languages, from benchmarking each one against well-known projects.

- Fixed: csharp.blocking-on-task reports .Result, .Wait(), and GetAwaiter().GetResult() in async code and ASP.NET controllers, not in synchronous methods that wrap async ones, such as an override of EF's SaveChanges, nor under a #pragma that disables CA1849 or VSTHRD002 for it. Tests and benchmarks are skipped for it, async void, and insecure serializers.
- Fixed: Folders named UnitTests, IntegrationTests, and FunctionalTests count as tests.
- Fixed: PHP's security checks skip tests. php.include-variable-path and php.command-built report paths and commands built from request input, directly or through a variable, not from a program's own directories, configuration, or escaped arguments. php.sql-string-built reports an interpolated value where SQL expects one, not an expression that builds the statement, such as a column list or a CASE. Have I Been Pwned lookups and HTTP Digest authentication are not password storage.
- Fixed: Ruby's security checks skip tests and specs, Redis and cache calls are not SQL, to_sql is escaped, class_eval and module_eval heredocs that define methods are reported only with request params, VERIFY_NONE behind a verification setting is the operator's choice, and commands in rake tasks and bin, exe, and script folders are developer tooling.
- Fixed: kotlin.global-scope skips tests, and it and kotlin.run-blocking-in-production skip benchmarks, which launch and block to measure coroutines.
- Fixed: shell.unquoted-expansion skips zsh code (a .zsh file, a zsh shebang, or zsh-only syntax), since zsh does not split unquoted expansions; powershell.invoke-expression and powershell.global-variable skip tests; swift.http-url-literal skips documentation catalogs and examples.

## v1.2.0 (2026-11-03)

More accurate findings: fewer false ones across Django, React, and Go, and the official engine can judge a file by the project around it.

- Improved: The official build's engine reads a project's files once before checking them one at a time, so a finding can depend on the rest of the project, such as validation done in another file. Each file is still analyzed in isolation, and nothing leaves your machine.
- Fixed: java.unsafe-deserialization reports objects read from a connection or request (getInputStream()), not a stream a serialization library's API takes or bytes the program wrote itself; java.trust-all-certificates honors @SuppressFBWarnings and @SuppressWarnings and an explicit option to skip verification, such as -noCertificateCheck; java.sql-string-built skips tests.

- Fixed: Django's settings.py, urls.py, wsgi.py, asgi.py, and manage.py are checked again. Their "Generated by 'django-admin startproject'" header made them count as generated code, so findings such as DEBUG = True were never reported. Migrations, which Django does generate, are still skipped.
- Fixed: react.hook-in-condition no longer flags a hook whose call always runs, such as `useTheme() ?? fallback` or `useAuth().user?.name || "guest"`: only the right side of `&&`, `||`, and `??`, and the branches of `?:` and `if`, are conditional.
- Fixed: go.sql-string-built reports a value spliced where SQL expects one (inside quotes, or after a comparison or LIKE), not table and column names, placeholder lists, or integers, which drivers and migrations must format in. On 15 well-known Go projects its findings fell from 82 to 0.
- Fixed: go.tls-insecure-skip-verify, go.sql-string-built, go.shell-command, and go.context-background-in-handler skip tests, and InsecureSkipVerify marked //nolint or #nosec is a reviewed decision.
- Fixed: go.context-background-in-handler allows a fresh context after <-ctx.Done(), as a graceful shutdown needs; go.http-without-timeout allows a client with its own Transport, and DefaultClient or a client without Timeout in a function bounded by a context.

## v1.1.0 (2026-11-03)

Uploads tell urfluency.com how much logic your code holds, and the official build gains urFluency's private engine.

- New: The official build, the one Homebrew installs, runs urFluency's private engine beside the open rules. It reads files only, like the rest, and your code still never leaves your machine. `urfluency version` names the engine a build runs, and uploads report it.
- New: Each language's facts count its functions and their complexity on your own lines, so the official score can judge a small project by the logic it holds rather than its line count. Nothing about your code beyond those counts is sent.
- Improved: `urfluency check` names the files it could not read, outside tests, since any of them keeps it from saying nothing was found; `--json` lists them as `unread`.

## v1.0.3 (2026-11-02)

Fewer false alarms from `urfluency check`, tested against 44 well-known open-source projects.

- Fixed: A Firebase web API key in an env file or Firebase App Hosting's `apphosting.yaml`, and an Algolia search key beside its app ID and index name, are not reported as secrets. Both ship to every browser by design.
- Fixed: A regular expression's `exec()` or a model's `eval()` beside a network request is not reported as fetching and running code.
- Fixed: Text that names `.npmrc`, `.netrc`, or `.pypirc` is not reported as reading them; code that builds a path to them in the home folder still is.
- Fixed: Install hooks that run only the project's own dependencies or common build tools, such as `husky`, `prisma generate`, or `npm run build` to `tsc`, are notes rather than reasons to review. A hook that runs a file from the repository, or downloads anything, is reported as before.
- Fixed: Copying the environment for a subprocess, as `os.environ.copy()` does, is not reported; serializing all of it still is.
- Fixed: Findings in tests and example code, such as a scanner's attack strings kept as test data or a demo's session secret, are listed as notes and do not change the verdict, and an oversized test fixture does not make a scan incomplete.
- Fixed: Example URLs such as `scheme://[user:passwd@]host`, placeholder values such as `API_KEY_UNUSED`, base64 images and fonts, and passwords in Docker Compose files are not reasons to review.

## v1.0.2 (2026-11-02)

- Fixed: Projects without Git that hold no code, only files such as a Dockerfile, are counted in an upload's facts, with their tools, so the official score counts them as the local estimate does.

## v1.0.1 (2026-11-02)

Official scores, and a new home and license. Uploads need this version or later.

- New: Uploads carry the counts behind your ratings, and urfluency.com scores them with its official model. Your profile and badges show the official score; when the model improves, your profile is rescored without uploading again.
- New: The CLI's own scores are labelled a local estimate. Its open model may differ from the official one by a few points, and sometimes by a level.
- Improved: The CLI now lives at rburns629/urfluency-cli, under the Functional Source License (FSL-1.1-MIT): use, change, and share it for anything but a competing product, and each version becomes MIT two years after its release. Versions before 1.0.0 stay MIT.
- Improved: Earlier versions can no longer upload. Upgrade with `brew upgrade urfluency`.

## v0.4.0 (2026-11-01)

A hardening release: a stricter safety check, fewer false findings, and Go 1.27.3.

- Security: The safety check reads install files first, every install hook, encoded scripts, HTML, and dependency folders committed to a repository, and closes four ways to hide a payload from its line rules.
- Security: A safety check that cannot read a folder or does not finish reports an error, never a clean result.
- Security: Clones stop once their download or file count passes a limit, and repository URLs with escaped characters are refused.
- Security: The CLI never follows a redirect to another site with your token, and refuses a login without an expiry.
- Security: Uploads are checked for identifying data in keys and version fields.
- Security: Text from scanned repositories is printed with control characters escaped.
- Security: Scans never read protected files such as certificates, however their names are capitalized.
- Improved: Each file is analyzed on its own within a time budget, so one hard file cannot stall a scan.
- Improved: Secret detection catches prefixed names and unquoted config values.
- Improved: Quality gates are scored against the gates that apply to each project.
- Improved: `vulns` asks before downloading a database, and never reads one from the current folder.
- Improved: Report format 0.5 and rule catalog 0.13.
- Improved: Built with Go 1.27.3. Release builds record their build image and carry provenance attestations.
- Fixed: Misreadings in the C++, Rust, Java, Go, C#, Shell, PowerShell, and Python analyzers, and a crash on `exec.CommandContext()` with no arguments.
- Fixed: Python local versions match vulnerability ranges, and suggested upgrades are compared the way each registry orders versions.
